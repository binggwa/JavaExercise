# 1. HashSet
***
- Set : 중복 원소를 허용하지 않는 집합
- Hash : 임의의 길이를 갖는 데이터를 고정된 길이(32bit, 256bit, 512bit ...)의 데이터로 변환하는 것
- Hash Function : Hash 기능을 하는 함수
- 다이제스트 : 해시함수에서 얻어진 값

### 왜 Hash를 이용하는가?
- ArrayList, LinkedList 등 자료구조에서 "특정 값"을 찾아내기 위해 배열, 노드를 순회해야만 한다.
- Hash는 동일한 값에 대해 동일한 다이제스트를 가지므로 순회할 필요가 없다.
- 이 다이제스트를 배열의 index로 활용하는 것이다.

#### hashCode()
- Java에서 제공하는 간편한 해시함수
- 객체의 주소값을 이용하여 해시 알고리즘에 의해 생성된 고유의 정수값을 반환한다.
- 객체가 같은 메모리 주소를 가리키고 있다면, 같은 정수값을 얻을 것이다.
```java
int a = X.hashcode(); 
```
- 객체가 같은 내용을 지니더라도, **가리키는 주소가 다르면 다른 값을 지니는 것**에 유의
- String, Integer, Double 등 **기본 자료형**이라면 override를 통해 객체 내용이 비교될 수 있도록 재정의하고 있어, 같은 내용일 경우 동일한 값을 갖는다.
- 사용자 클래스를 사용할 경우, 객체 내용을 비교하기 위해선 **클래스 내에 hashCode 메서드를 오버라이드** 해주어야 한다.

### 해시 충돌
- 해싱된 값이 같은 경우를 *해시 충돌*이라 한다.
- Java에선 단일 배열에 대해 약 21억 크기까지만 생성이 가능하지만, 메모리낭비가 심하다.
- 이 때문에, 배열의 사이즈를 줄여 X개의 인덱스가 있을 때, 다음과 같이 지정한다.
```java
int index = Math.abs(A.hashCode()) % X;
```
- hashCode()가 음수 값이 나올 수도 있으므로 절댓값으로 변환하는 것이 필요

#### Open Addressing
- 해시 충돌이 발생할 경우, 빈 곳을 찾아가서 채운다.
- 장점
  - 해시 충돌이 일어날 가능성이 적어 데이터의 개수가 적을수록 속도가 빨라진다
  - 연속된 공간에 데이터를 저장하기 때문에 캐시 효율이 좋아진다.
- 단점
  - 해시충돌이 발생하면 객체의 인덱스 값이 바뀌어 버린다.
  - 부하율(load factor), 테이블에 저장된 데이터의 개수가 많아질수록 성능이 급격하게 저하된다.

#### Separate Chaining
- 연결리스트 형식으로 같은 인덱스에 새로운 노드를 연결한다.
- 최악의 경우 해시충돌에 의해 한 개의 인덱스에 여러 개의 노드가 연결될 수도 있다.
- 자바 내부에서 이럴 경우, **인덱스의 LinkedList를 Binary Tree로 변환하여 색인 속도를 높인다.**
- 장점
  - 해시충돌이 일어나더라도 연결리스트로 노드가 연결되므로 index가 변하지 않는다.
  - 테이블의 각 인덱스는 연결리스트로 구현되기 때문에 데이터 개수의 제약을 거의 받지 않는다.
- 단점
  - 부하율에 따라 선형적으로 성능이 저하된다. 즉, 부하율이 작을 때는 Open Addressing이 더 빠르다.
